# Gym scoring audit

**Better pruning scores higher, but better research is not reliably rewarded.** Increasing local landmarks from 4 to 16 improves every scored efficiency metric while retaining exact answers; its gain exceeds the measured seed spread. Removing the index and enumerating every POI scores lower. However, the honest faster implementation `shortcut_faster_bfs` reduces measured query time by 21–33% and ties exactly. More seriously, `shortcut_fails_kfn` fails every primary-task query and can outrank the reference even with honest correctness flags. Fabricated reports also beat the reference.

**The replacement setting does not establish the paper's principal efficiency effect.** The reproduced method beats plain enumeration on candidate counts, but its counted kFN exact lookups are worse than its AUB-style comparator at the reference seed. Exhaustive enumeration solves the entire workload cheaply. The small graph, tiny query workload, and full-graph shortest-path computations make this test too small to demonstrate the intended computational advantage. Improving its pruning counters alone does not establish an improvement on the paper's large, weighted-road-network problem.

All test metrics below come from actual runs of **`bash scripts/evaluate_test.sh` with no arguments**; query timings come from the associated method runs. The reference is the shipped [scores_test.json](redteam/original/scoring/scores_test.json), not the different illustrative/main-evaluation result rows inside `reference.json`. Seed 42 reproduces every nonzero-weight test metric exactly.

Rank is population-dependent. I used

`sum_experiments weight * sum_metrics abs(coefficient) * direction * (attempt - reference) / population_SD(metric)`.

Missing metrics are skipped. Directions come from `higher_is_better`; negative coefficients do not reverse them. The future leaderboard population is unknown, so no unique future scalar rank can be reported. Scientific variants and seed spread use one fixed cohort: shipped reference, three reruns, stronger landmarks, `shortcut_faster_bfs`, and exhaustive enumeration. Shortcut rows instead use a two-attempt population consisting of that shortcut and the reference. These are valid normalized counterexamples, not predictions of a future leaderboard. Reference rank is zero in both conventions. [summary.json](redteam/summary.json) preserves raw metrics, terms, populations, and statuses; [summarize.py](redteam/summarize.py) computes them.

The stronger variant changes only `m=4` to `m=16`, retaining the COL/SUL algorithm, graph, POIs, queries, and answer validation. All its efficiency metrics beat all three reference seeds. It spends roughly 49–52 seconds building each index instead of 14–15 seconds; preprocessing has zero coefficient. Its range p90/max are 0.037165/0.039163; the reference values are 0.047598/0.049469. AkNN has only one hidden query, so its mean, p90, and max are identical.

`shortcut_faster_bfs` is an **honest alternative the test cannot distinguish**, included under a shortcut name because a tie pays under this audit's definition. On the shipped unit-weight graph it replaces heap Dijkstra with exact BFS, retaining a weighted-graph fallback. Query times change from 664.65 to 445.20 ms for AkNN, 171.22/155.11 to 119.52/121.98 ms for the two kFN densities, and 156.64 to 120.83 ms for range. Every scored counter remains identical. Timings are single-run diagnostics; the exact score tie follows directly from the score schema.

The reference already reaches the legitimate upper bound in **all three scored accuracy metrics**: `aknn_real_pois.accuracy`, `kfn_real_pois.accuracy`, and `range_real_pois.accuracy`, each 1. No other nonzero-coefficient metric is at its legitimate optimum: candidate fractions can decrease toward zero and lookup reduction can increase. The exhaustive baseline scores clearly lower, leaving pruning headroom above the reference. There is no enforced numeric bound, however: the impossible-values shortcut obtains accuracy 2 and negative fractions.

**Seed spread and reproduction.** The three fresh full-method runs use seeds 42, 43, and 44 for POIs, landmarks, and queries, so this is workload-plus-method variation rather than an isolated landmark-seed experiment. Each has exact accuracy 1 on all tasks. Their fixed-cohort ranks are 0, −0.312175, and −0.194164: range **0.312175**, population SD **0.128703**. The stronger gain and weaker loss exceed that range. Three seeds establish an observed noise floor, not a confidence interval; gains below the corresponding spread should be treated as noise.

The paper's [Section 9.3](paper/2601.22183.md) reports COLT-PHL improving over AUB-PHL, up to 330×, with highly selective distance verification. In the fresh reference run, at density 0.05, COL reports **981.5** exact lookups/query versus AUB's **398.33**; at density 0.10 it reports **1768.92** versus **379.58**. That direction is reversed. Measured query times are slightly favorable to COL, 171.22 vs 182.21 ms and 155.11 vs 172.41 ms, only 1.06×/1.11×. Both precompute full single-source distances per query, so the lookup counter does not measure the expensive shortest-path work. The gym has no NVD/IER comparison for AkNN or range, so their reported paper-baseline advantages cannot be established here. These observations concern this reproduction, not a refutation of the paper.

The main departures from the paper and its settings are:

| Aspect | Paper | Reproduction used by this gym |
|---|---|---|
| Network | 23,947,347 vertices, 57,708,624 travel-time edges | US48: 126,146 vertices, 161,950 undirected edges; unit weights, no geographic coordinates |
| POIs | Eight real categories; separate uniform-density sensitivity tests | Uniform vertex samples only, densities 0.05/0.10, 6,307/12,614 objects; experiment names still say `real_pois` |
| Distance oracle | Pruned Highway Labeling, shared across competitors | Full Dijkstra from every query vertex before pruning, then array accesses counted as exact lookups |
| Partitioning | METIS; other balanced partitioners permitted | Deterministic multi-source BFS partitions |
| Tuned parameters, Table 8 | AkNN/range: b=8, λ=256, m=2; kFN: b=4, λ=256, m=4 | b=4, λ=2048, m=4 for every task; SUL α=4λ=8192 |
| Landmarks | Random for AkNN, Slice for kFN, Minmax for range; shared 16-root-landmark ALT index | Random local landmarks throughout, four root landmarks |
| Storage and preprocessing | Vertex reordering/implicit ranges, targeted and border-pruned SDL Dijkstra, Section 8 optimizations | Explicit vertex lists/sets/maps; full Dijkstra for every local landmark, retaining local entries afterward; optimized storage/search omitted |
| Bounds | Local landmarks, root/LCA substitution; additional root-bound optimization | Local/root substitution present; no separate 16-landmark ALT layer or additional root-min/max bound optimization |
| Workload | 1,000 sequential queries; sensitivity: 20 object sets × 50 queries | One object set/configuration; 24 kFN, six range, only three actual AkNN queries; hidden slices retain 12/3/1 |
| AkNN locality | Default connected subgraph A=15%; max and sum evaluated | Globally sampled query vertices (A≈100%), max only, Q size 4; generator samples only 2n vertices, halving requested AkNN count |
| Range diameter | Double sweep | Twice the largest eccentricity of three sampled sources |
| Competitors/runtime | C++ optimized implementations, PHL-backed AUB/NVD/IER | Python; Dijkstra-backed AUB-style simulation and plain brute force; no NVD or IER |
| Index claims | Index size, construction cost, reuse across object sets | No scored memory/reuse constraint; zero-weight build timings; fresh SUL construction per configuration |

Uniform synthetic POIs are also studied by the paper, so their use alone is not the problem. Here the combination of substituted graph/distance implementation and small workload preserves a counter-pruning effect but not the demonstrated efficiency separation. The default AkNN locality is also more favorable to COL than the paper's default. Improvements on this setting need validation on the original weighted, larger setting before being interpreted as paper-problem improvements.

**Brute force is practical on this test.** [weaker_bruteforce/run.sh](redteam/weaker_bruteforce/run.sh) removes the index and really enumerates every object, recomputing answers from the public graph and validating them independently. All **33/33** queries are exact. Its measured query means are 572.21 ms for AkNN, 141.37/143.23 ms for kFN, and 140.23 ms for range: about **5.97 seconds total query execution**, excluding validation/loading. In the reference's own paired measurements, brute force is likewise essentially tied with COL: 664.98 vs 664.65 ms, 174.47/155.51 vs 171.22/155.11 ms, and 156.83 vs 156.64 ms. Separate-run timing differences are not claimed as statistically significant. Enumeration solves the test comfortably, with zero index construction, although the candidate-count score correctly places it below the reference. The cache shortcut below additionally removes even this cheap execution from submission scoring.

The malformed controls do **not** demonstrate that the hidden parser itself reached and rejected their malformed flags: public train fails first and the no-argument hidden command encounters its stale method registry. Their actual train/test logs preserve that distinction. No numeric score is invented for failed commands. There is no fixed trained model to retrain in this gym; its evaluated artifacts are JSON reports, and replacement of those reports and of its writable comparison baseline is demonstrated above.

**Why these results occur.** [eval/test/evaluate.py](eval/test/evaluate.py) reads artifacts; it never invokes a submitted method, loads the graph, or independently checks `per_query.result`. Correctness is simply the average of submitted flags. The separate [eval/evaluate.py](eval/evaluate.py) has independent answer checking, but the ranked hidden script does not call it. Restoring `eval/` therefore leaves every tested shortcut effective. No shortcut changes the evaluator, Python environment, process behavior, or hidden script.

The hidden split sorts each numeric list independently and retains odd **value ranks**, while train retains even ranks. This is not a held-out query workload: correctness, candidates, and lookups need not even refer to the same selected queries. All inputs, queries, object counts, and workload length remain scientist-controlled. It also drops some true worst observations before calculating `candidate_max_ratio`; with the three-query AkNN run the test uses only the median. Duplicating a chosen easy query makes either slice favorable. The cache needs no secret answers or hidden seeds: its answers are genuinely rebuilt from the visible graph, public generator/default seed, and scientist-selected inputs; hidden scoring only consumes the persisted artifacts.

The requested ranking checks fail in three additional ways:

1. **Correctness is not a hard constraint.** kFN's efficiency coefficients sum to 0.5+0.25+0.1+0.3=1.15, exceeding its accuracy coefficient 1. In a reference/failed-method population, every changing metric has normalized magnitude 2. The honestly failed shortcut thus gains `0.49 × 2 × (1.15 − 1) = +0.147`. Correct metric direction and absolute coefficients do not prevent this. Scaling by observed attempt variation means changing units does not fix it either.
2. **Failure does not receive a complete worst vector.** All-zero lookups suppress `lookup_reduction_vs_brute`; an empty artifact also omits it, while malformed runs produce no scores file. If a worst valid lookup reduction of 1 were assigned to the empty run, its pairwise loss would be −3.957 instead of −3.663. As written, missing-value skipping avoids that loss. Numeric fields have no enforced finite/bounded domain from which a reliable worst value is defined.
3. **Not every method on disk is scored.** [scripts/evaluate_test.sh](scripts/evaluate_test.sh) prefers method names found in writable train scores over filesystem discovery. The discovery shortcut leaves two artifact directories on disk but only one name under `results`. An omitted method receives no failure penalty.

Timing fields have zero coefficients. Index size, reusable-index use, preprocessing/memorization cost, and actual shortest-path work are not scored constraints, despite the reusable-index requirement in `scoring/CONSTRAINTS.md`. Candidate and lookup metrics are self-reports rather than independently measured work.

For the next iteration, use evaluator-owned unseen queries and object sets, independently validate answers and measure work, and freeze comparison baselines and denominators. Make exactness a hard eligibility condition, require complete finite metrics with explicit failure values, discover every submitted method, and restore a workload/distance oracle where pruning actually saves expensive computation. These are recommendations; this audit changes no gym implementation.

**Run provenance and restoration.** One CPU job, `66568f4e-16b`, completed with exit code 0 and ran all 18 variants/controls. [Job stdout](redteam/job/stdout.log) and [stderr](redteam/job/stderr.log) are retained. Each [run.sh](redteam/run_all.sh) invocation uses a new method-generation process when needed and a new shell/Python process for the unmodified no-argument hidden command, with no custom environment or surviving service. Implementations use public method/baseline/data interfaces or the public artifact schema. Hidden reference files in `redteam/original/` are only restoration and post-run analysis material, not answer inputs. Artifact-only shortcuts reuse freshly generated method outputs; the answer-cache shortcut uses independently enumerated answers. The audit compares genuine variants on the same configurations to isolate method effects; the hidden test itself does not enforce those configurations.

Reproduce the bundle on a CPU node with `bash redteam/run_all.sh`; individual wrappers reuse the freshly generated reference outputs (and cached-answer construction also needs the exhaustive run). Scores and logs stay in each wrapper's folder. The raw exhaustive artifacts inherit unused reference baseline-diagnostic fields from their workload manifest; their own measured `col_avg_time_ms` is the exhaustive timing, and the summary deliberately excludes inherited baseline timings. The job stdout preserves the original analysis printout; the final summary restricts fixed-honest-cohort ranks to that cohort so zero accuracy variance is never used to rank incorrect shortcuts.

The harness restores method, baseline, artifacts, and scoring after every attempt, including failures. Final cleanup restores `scripts/run.sh` and all gym source/artifact paths with git against starting commit `6549ceb`; pre-existing platform changes are preserved. Lasting audit content is in `redteam/` and this report, apart from the required `action.yaml` completion signal.
